# otterpebble 아케이드 — 「바로 해보기」 데모 게임

featurephone 셸의 「바로 해보기」용으로 새로 만든 작은 MIDP 게임이다. 지금은 **한 개**다(2026-09-29 운영자 지시로
나머지 데모를 걷어 내고 몽글셋을 이 게임으로 키웠다). 틀(`src/Arcade.java`) · 효과음 조립기(`src/Sound.java`) ·
컴파일 스텁(`stubs/`) · 빌드 조리법(`build-game.sh`)이 여기 있고, 게임은 `demo/<게임>/` 에 `src/` · `art/` · `LICENSE` ·
`MANIFEST.MF` · `build.sh` · `playthrough.keys` 를 둔다.

| 게임 | 디렉터리 | 한 판 | 조작 |
|---|---|---|---|
| 동물줄맞춤 — 같은 동물 셋을 한 줄로 | `dongmul-julmatchum` | 시간 막대가 다 줄 때까지(쉬움 90초 · 보통 60초 — 화면에는 숫자 없이 막대만) | 2 4 6 8 · 방향키 고르기 · 5 집기 → 방향키 바꾸기 · L/R/CLR 일시정지 |

틀이 주는 것 — 일반 피처폰 게임의 화면 구조(2026-09-29):

- **시작**: 만든 곳 서명 로고(조약돌 셋이 쌓이고 `otterpebble` · 첫 실행 약 1.8초 · 그다음부터 0.6초 · 아무 키나 건너뛰기) →
  타이틀(게임이 그린다 · 「아무 키나 누르세요」 깜빡임) → 메인 메뉴.
- **메인 메뉴**(아이콘 + 글자 · 고른 줄은 크고 어둡게): 게임 시작(난이도 카드) · 이어하기(일시정지한 판이 있을 때만) ·
  게임 방법(목차 → 쪽 · 4 6 넘김 · CLR 목차로) · 설정(소리 · 진동 · 난이도 · 움직임) · 최고 기록(5 로 기록 지우기 확인) ·
  제작자 정보(이름 · 버전 = `MIDlet-Version` · 만든 곳 · MIT · 사이트) · 게임 나가기(확인 뒤 `notifyDestroyed`).
- **일시정지**: 게임 중 L · R · CLR. 시간 막대가 멈추고 판을 가린다. 계속하기 · 게임 방법 · 설정 · 처음 화면으로(확인) · 게임 나가기(확인).
  일시정지하는 순간 판을 레코드에 저장한다 — 그래서 셸을 닫았다 다시 열어도 이어하기가 뜬다.
- **소프트키 라벨**: 모든 화면 아래에 L/R 이 지금 하는 일(선택/뒤로 · 게임 중 「메뉴」 · 확인 카드는 예/아니오).
- **키**(wie 에서 `keyPressed` 로 오는 값, 탐침 MIDlet 으로 실측): L 소프트키 `6` · R 소프트키 `7` · CLR `8` · 종료(HANGUP) `-1`.
  L = 선택, R · CLR = 뒤로, 종료 키 = 어디서든 「나가시겠어요?」. 다른 단말 관례인 음수(`-6` `-7` `-8`)도 받는다.
- 저장: 최고 점수(난이도별) · 설정 · 로고 본 적 있음 · 일시정지한 판을 `RecordStore`(게임 이름) 한 레코드에 둔다.
  옛 11 · 12 바이트 레코드도 읽는다.

## 움직임(애니메이션)

동물줄맞춤의 판은 단계로 움직인다: 교환 미끄러짐 → (못 맞추면) 기울었다 돌아옴 → 터질 얼굴이 웃음 → 고리 두 번 →
위 얼굴이 가속하며 떨어지고 착지 때 살짝 내려앉음 → 또 맞으면 「연쇄 xN」 배지 · 점수는 「+N」 으로 떠오른다.
무입력이 이어지면 둘 수 있는 한 쌍이 고리 · 놀란 눈 · 흔들림으로 힌트를 주고(첫 기록 전에는 더 빨리), 둘 수 없는 판은
새 판이 위에서 떨어지며 섞인다. 끝 카드는 점수가 올라가며 세어지고 새 최고 기록이 깜빡인다.

- **길이는 전부 루프 프레임 수**다(밀리초 아님) — 느린 기기에서는 같은 동작이 느리게 보일 뿐 규칙은 같다.
- **입력은 기다리지 않는다**: 커서 이동 · 집기는 언제나 즉시, 움직이는 중에 교환을 누르면 남은 움직임을 한 번에 끝내고
  그 교환을 바로 시작한다(`finish()`). 그래서 입력 → 첫 반응은 애니메이션 전과 같다(측정: 회차 문서).
- **설정 「움직임」**: 켬 = 전부 · 줄임 = 터질 얼굴 1프레임만(미끄러짐 · 낙하 · 흔들림 · 떠오름 없음) ·
  끔 = 판이 키를 누른 그 프레임에 바로 바뀐다(점수 「+N」 은 움직이지 않는 글자로 남고, 연쇄는 아래 알림으로).
- 표정 그림 2벌(웃음 `f<k>_30h.png` · 놀람 `f<k>_30a.png`)도 `art/Faces.java` 가 빌드 때 그린다.

## 저작권

우리 저작물이다 — **MIT**(게임 디렉터리 `LICENSE`, jar 안에 `LICENSE.txt`).
**빌린 것은 장르의 규칙뿐**이고, 이름 · 그림 · 소리는 전부 새로 만들었다. 동물 얼굴은 `art/Faces.java` 가 빌드 때
Java2D 도형으로 그려 PNG 로 넣고, 나머지 화면은 `Graphics` 호출로 그린다. 글자는 호스트 글꼴(neodgm), 효과음은
`Sound.java` 가 음표 목록을 SMAF 로 조립한다 — 외부 코드 · 그림 · 글꼴 · 소리 파일 0.
얼굴은 일부러 기존 캐릭터 묶음(애니팡 · 주주클럽 · 카카오프렌즈 · 라인프렌즈 · 산리오 · 포켓몬 · 동물의 숲)과
다르게 그렸다: 흰자 없는 작은 점 눈 · 볼터치 없음 · 표정은 짧은 선 하나 · otterpebble 톤의 탁한 파스텔.
섞는 순간 이 절이 거짓이 된다.

## 디자인

otterpebble `DESIGN.md` 의 밝은 무채색 토큰(바탕 `#F4F5F7` · 카드 `#FFFFFF` · 글자 `#191F28`/`#616B78`) 위에
동물 여섯 색만 얹는다. 호스트 글꼴은 크기가 하나뿐이라(엔진의 `Font` 가 크기를 무시한다) 위계는 굵기(1px 겹쳐 그리기)와
색으로 낸다. 색만으로 가르지 않게 동물마다 귀(둥근 귀 · 작은 옆귀 · 뾰족 귀 · 긴 귀 · 귀 없음+얼굴 가면 · 눈 혹)가 다르다.

화질: 엔진 화면은 240x320 고정이고(셸 `SCREEN_W/H` · 게임이 바꿀 수 없다) `Graphics` 도형에는 안티앨리어싱이 없다.
그래서 곡선이 많은 얼굴은 빌드 때 부드러운 가장자리(알파)로 그린 PNG 를 쓰고, 엔진 `drawImage` 가 알파를 섞는다.

## 빌드

```
demo/<게임>/build.sh      # → demo/<게임>/out/<게임>.jar (+ sha256)
```

조리법은 `build-game.sh` 하나다(JDK 11~19 · `--release 7` · preverify 없음 · `stubs/` 로 엔진에 없는 API 는 컴파일
단계에서 실패 · `art/*.java` 가 PNG 를 그림 · `jar --date` 고정 → 같은 JDK 면 같은 바이트). 이유는 그 파일 머리주석에 있다.
jar 는 커밋하지 않는다(`*.jar` git-ignore · leak audit 이 추적 jar 를 거부).

## 확인

```
cargo run -q --release -p wie_cli --bin wie_validate -- --inject --boot-secs 1.5 --max-ticks 100000000000 \
  --keys demo/<게임>/playthrough.keys --shotdir <dir> demo/<게임>/out/<게임>.jar
```

`playthrough.keys` 는 로고 → 타이틀 → 메뉴 → 게임 방법 → 설정 → 최고 기록 → 제작자 정보 → 시작 → 일시정지 → 계속 → 일시정지 → 처음 화면으로 → 이어하기 → 시간 끝 → 게임 나가기까지 한 번에 가는 키 목록이다
(판이 무작위라 눈 감고 누른다). `result PASS` · `stop "clean exit"`(게임 나가기) · `java_exceptions.count 0` · `audio.plays > 0` 과 `--shotdir` 의 장면을 본다.
