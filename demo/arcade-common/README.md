# otterpebble 아케이드 — 「바로 해보기」 데모 게임 7종

featurephone 셸의 「바로 해보기」용으로 새로 만든 작은 MIDP 게임들이다. Pebble Snake(`../pebble-snake/`)와
같은 방식으로 빌드하고, 모든 게임이 틀(`src/Arcade.java`) · 효과음 조립기(`src/Sound.java`) · 컴파일 스텁(`stubs/`)을
함께 쓴다. 게임마다 `demo/<게임>/` 에 `src/` · `LICENSE` · `MANIFEST.MF` · `build.sh` · `playthrough.keys` 가 있다.

| 게임 | 디렉터리 | 한 판 | 조작 |
|---|---|---|---|
| 몽글셋 — 같은 알 셋을 한 줄로 | `monggeul-set` | 60초 | 방향키·2468 고르기 · 5 집기 → 방향키 바꾸기 |
| 쏙쏙 두더지 — 올라온 두더지를 톡 | `ssokssok-mole` | 30초 | 1~9 = 그 자리 구멍 |
| 곱절 타일 — 같은 숫자를 밀어 합치기 | `gopjeol-tile` | 8 을 만들거나 막히면 끝 | 방향키·2468 밀기 |
| 밤송이 찾기 — 숨은 밤송이 10개 피하기 | `bamsongi-field` | 다 열거나 밟으면 끝 | 방향키·2468 고르기 · 5 열기 · # 또는 * 표시 |
| 차곡차곡 — 줄을 채우거나 같은 색 셋 | `chagok-stack` | 조각 둘 자리가 없으면 끝 | 4 6 옮기기 · 2 5 돌리기 · 8 바로 내리기 |
| 뽁뽁 풍선 — 같은 색 풍선을 이어 터뜨리기 | `bbokbbok-balloon` | 목숨 셋 · 풍선이 물에 닿으면 끝 | 4 6 오리 옮기기 · 5 조약돌 던지기 |
| 통통 조약돌 — 판자로 튕겨 그림 타일 깨기 | `tongtong-pebble` | 그림 셋을 다 깨거나 목숨 셋 | 4 6 판자 옮기기 · 5 띄우기 |

모든 게임 공통: 첫 화면이 조작 안내 · 5 로 시작/다시하기 · **0 = 소리 켬/끔** · 최고 점수는 `RecordStore`(게임 이름) 에 저장.
밤송이 찾기의 표시 키가 0 이 아니라 # · * 인 이유: 0 은 모든 게임에서 «소리» 로 같게 두었다.

## 저작권

모든 게임이 우리 저작물이다 — **MIT**(각 디렉터리 `LICENSE`, jar 안에 `LICENSE.txt`).
**빌린 것은 장르의 규칙뿐**이고, 이름 · 그림 · 소리는 전부 새로 만들었다. 그림은 `Graphics` 호출(둥근 사각형·원·선)로만
그리고, 글자는 호스트 글꼴(neodgm), 효과음은 `Sound.java` 가 음표 목록을 SMAF 로 조립한다 — 외부 코드 · 그림 · 글꼴 ·
소리 파일 0. 원작 게임의 이름 · 캐릭터 · 화면 구성 · 레벨 배치 · 선율을 쓰지 않는다. 섞는 순간 이 절이 거짓이 된다.

차곡차곡(떨어지는 조각 쌓기 장르)은 규칙 외의 «시각 표현» 을 일부러 비켜 갔다 — 놀이판 8x13, 1~3칸 조각 4종 + 둥근
「펑」 조각, 조각 모양과 무관한 칸별 색, 착지 그림자 없음, 다음 조각 미리보기 없음, 게임 끝 연출 없음, 효과음만.
자기 규칙은 «같은 색 3칸이 가로·세로 한 줄로 닿아도 사라지고, 남은 칸이 하나씩 떨어져 연쇄» 다.

실시간 두 게임(뽁뽁 풍선 · 통통 조약돌)도 같은 원칙이다. 뽁뽁 풍선은 편대가 한 덩어리로 좌우로 흔들리며 한 줄씩
내려오고, 원작의 적 모양 · 붙잡아 가기 · 보너스 판 · 날아 들어오는 연출이 없다 — 적은 풍선, 규칙은 «같은 색 연달아 = 배수».
통통 조약돌은 판마다 우리 그림(튤립 · 집 · 물고기)이 타일로 놓이고, 아이템 · 레이저 · 보스가 없다 — 규칙은 «깨진 타일
바로 옆 같은 색도 함께». 둘 다 격자 위에서 한 프레임에 한 칸만 움직이고 난이도를 프레임 수에 묶어, 4fps 에서는
느려질 뿐 관통 · 순간이동이 없다.

## 디자인

otterpebble `DESIGN.md` 의 밝은 무채색 토큰(바탕 `#F4F5F7` · 카드 `#FFFFFF` · 글자 `#191F28`/`#616B78`) 위에
게임마다 파스텔 3~5색 한 벌만 얹는다. 선택은 굵은 둥근 테두리, 점수·시간은 상단 바 한 줄. 호스트 글꼴은 크기가
하나뿐이라(엔진의 `Font` 가 크기를 무시한다) 위계는 굵기(1px 겹쳐 그리기)와 색으로 낸다. 색만으로 가르지 않게
몽글셋 알·차곡차곡 칸은 모양 표시를, 곱절 타일은 숫자 아래 점을 함께 그린다.

## 빌드

```
demo/<게임>/build.sh      # → demo/<게임>/out/<게임>.jar (+ sha256)
```

조리법은 `build-game.sh` 하나이고 Pebble Snake 의 `build.sh` 와 같다(JDK 9~19 · `--release 7` · preverify 없음 ·
`stubs/` 로 엔진에 없는 API 는 컴파일 단계에서 실패 · `jar --date` 고정 → 같은 JDK 면 같은 바이트). jar 는 커밋하지 않는다.
`stubs/` 는 Pebble Snake 의 것에 `RecordStore` · 숫자키 상수 · `drawRoundRect` 만 더했다(엔진 `wie-midp` 에 있는 것만).

## 확인

```
cargo run -q --release -p wie_cli --bin wie_validate -- --inject --boot-secs 1.5 --max-ticks 100000000000 \
  --keys demo/<게임>/playthrough.keys --shotdir <dir> demo/<게임>/out/<게임>.jar
```

`playthrough.keys` 는 한 판을 끝까지 가는 키 목록이다(판이 무작위라 눈 감고 누른다 — 게임 끝 카드가 나온 뒤의 5 는
새 판을 연다). `result PASS` · `java_exceptions.count 0` · `audio.plays > 0` 과 `--shotdir` 의 게임 끝 카드를 본다.
