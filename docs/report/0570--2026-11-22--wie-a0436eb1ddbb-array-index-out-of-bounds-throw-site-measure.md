### 2. 던지는 자리 · 배열 출처

- 던지는 자리: `GameCanvas.h(II)B` 오프셋 31 `baload`. 642번 모두 같은 자리이고, 인자도 642번 모두 `h(342, 255)` 다.
- 부르는 길(안쪽 → 바깥): `h(II)B` 31 ← `x(B)V` 43 ← `ap()V` 617 ← `a(ZZ)V` 1 ← `w()V` 9074(613번) 또는 7622(29번) ← `paint(Graphics)` 25 ← `Canvas.handlePaintEvent`. 게임 프레임 6개 어디에도 처리기가 없다(`handler=None`). 예외는 `paint` 밖으로 나간다.
- 배열: 정적 필드 `cq`(`[[B`). `<clinit>` 오프셋 6549~6555 가 상수 47 과 12 로 `multianewarray` 한다. 같은 꼴의 `cr`(47×12) · `cs`(31×12)가 바로 뒤에 있다. 초기화 `am()V` 도 `행 < 47` · `열 < 12` 로 돈다. 길이 12 는 지도의 열 수이고 실행 중에 바뀌지 않는다.
- `h(x, y)` 가 하는 일: `j(x, y)` 로 픽셀을 타일 칸으로 바꾼다(열 = x / 28 · 행 = (y / 14) × 2 뒤 모서리 표로 보정). 그 다음이 전부다 — 「행 < 0 이거나 열 < 0 이면 -3 을 돌려준다. 아니면 `cq[행][열]` 을 돌려준다.」 **아래쪽 검사만 있고 위쪽(열 ≥ 12 · 행 ≥ 47) 검사가 없다.**
- x = 342 면 열 = 342 / 28 = 12 다. 지도 너비는 12 × 28 = 336 픽셀이므로 342 는 동쪽 끝을 6 픽셀 넘은 자리다.

### 3. (342, 255) 는 어디서 오나 — 전부 게임 자신의 상수

- `ap()V` 는 걸어 다니는 개체(화면의 방문객) 30칸을 돌며 `x(i)` 를 부른다. `x(i)` 는 「지금 위치 + 방향별 한 걸음」 자리의 타일을 `h` 로 미리 본다. 예외 때의 `i` 는 3 · 4 · 5 · 6 이 차례로 나왔다.
- 개체를 내는 `ao()Z` 는 시작 타일과 방향을 정적 표에서 읽는다. `<clinit>` 에서 푼 값: 시작 표 `aD = [[13, 0, 2], [13, 0, 2], [7, 10, 1]]` · 걸음 표 `aH = [[-2, -1], [-2, 1], [2, 1], [2, -1]]`.
- 첫 두 행은 같다: 행 13 · 열 0 · 방향 2. `ao` 의 산수로 시작 픽셀은 x = 0 × 28 + 14 + 14 = 28 · y = 13 × 14 / 2 + 7 = 98 이고, 방향 2 의 한 걸음은 (+2, +1) 이다.
- 그 직선은 (28 + 2n, 98 + n) 이다. n = 157 에서 **(342, 255)** 가 된다. 잰 인자와 두 좌표가 모두 맞는다.
- ⇒ 넘는 인덱스는 「게임이 정한 시작 자리에서 게임이 정한 걸음으로 곧장 157걸음」의 결과다. 이 길(`h` · `j` · `x` · `y` · `ao` · `m` · `k`)이 부르는 것은 게임 자신의 메서드뿐이고, 플랫폼 API 호출은 0 이다. 걸음은 `paint` 한 번에 한 번이고 시각 API 를 읽지 않는다.
- 방향을 다시 고르는 `a(BZ)V` 도 같은 버릇이다. 이웃 칸을 볼 때 짝수 행 갈래는 아래쪽만 검사하고, 홀수 행 갈래는 검사가 없다.

### 4. 판정 — ⒜ 게임 자신의 버그

- 근거 1: 바이트코드에 위쪽 범위 검사가 없다(§2). 같은 메서드가 아래쪽은 -3 으로 막는다.
- 근거 2: 인덱스로 들어가는 값이 전부 게임의 정적 표와 그 산수다(§3). 엔진 API 의 반환값 · 시각 · 입력 어느 것도 이 계산에 들어가지 않는다. `Random` 은 방향을 다시 고를 때만 쓰이고(`abs(nextInt() % n)` — 어떤 값이 와도 범위 안이다) 곧장 걷는 동안은 쓰이지 않는다.
- 근거 3: 길이 12 인 배열의 12번 칸을 `baload` 로 읽으면 어느 자바 VM 에서나 같은 예외다.
- 한계: 원 단말에서 직접 본 것은 아니다. 방문객이 그 직선을 벗어나는 조건(놀이기구에 들어감 · 수명)은 읽지 않았다. 그래서 「모든 방문객」이 아니라 「직선 위에서 타일 종류가 바뀌지 않은 방문객」이 닿는다고만 말한다. 이 런에서 정책 키가 놓은 놀이기구는 그 직선 밖이었다.
- 엔진이 한 일: 예외가 `paint` 밖으로 나오면 그 프레임의 나머지 그리기가 빠지고 놀이는 이어진다(두 런 모두 stderr 에 `uncaught exception in thread` 0줄 · Q 런은 예외 뒤에도 키와 화면이 이어졌다). 예외가 나는 프레임에는 윗줄 표시와 캐릭터가 없다(증적 `run-Q-t060-t140.png` 의 t100~t140).
- ⇒ 엔진 수정 0 · `compat.json` · 진도 표기 변경 0 · 조정 행 0. 후속 티켓 제안도 0 이다.
