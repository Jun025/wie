## F2 — 고른 안과 «버린 이유» (대가 포함)

★**결정적 실측 하나가 후보를 갈랐다** — git 3-way 병합은 두 삽입 지점 사이에 **1줄**만 있으면 붙는다:

```
같은 지점       → CONFLICT      1줄 떨어짐 → clean
0줄 떨어짐      → CONFLICT      2~4줄     → clean
```

⇒ ★**「맨 위」가 병이 아니라 «지점이 하나»인 것이 병이다.**

| 안 | 판정 | 근거 · 대가 |
|---|---|---|
| ⒜ 맨 아래 append | ★**기각 — 효과 0** | 위 실측대로 **같은 지점이면 위든 아래든 충돌**한다. 4셀 모델(진행중×완료 = top×append)에서 **4셀 전부 2/2 충돌**. ★총괄 소견이 「가장 작다」고 본 안인데 ★**작은 게 아니라 아무것도 안 한다.** |
| ⒝ PR 번호 정렬 삽입 | ★**기각** | 지점을 «분산»시키는 발상은 옳지만 ★**이 저장소의 형제 회차는 PR 번호가 «연속»이다**(#120~#133 실측) ⇒ 슬롯이 다시 서로 인접한다. 대가: 정렬 규칙을 사람이 지켜야 하고 어기면 조용히 되돌아간다. |
| **⒞ 생성물화 — «고정 안내» 형태** | ★**채택** | 지점을 **없앤다**. 대가 ⑴**오프라인에서 못 읽는다**(`gh` 필요) ⑵**진행 중 회차의 서술이 이 파일에 안 남는다**(정본 = PR 본문·티켓 · 착지하면 「완료」로 들어온다). |
| ⒞′ 렌더해서 **커밋** | ★**기각** | 회차가 그 결과를 커밋하는 순간 ★**같은 줄을 다시 매 회차 고쳐 써 지점이 되살아난다** — 고정 안내보다 **엄격히 나쁘다**. |
| 회차별 파일 | ★**범위 밖** | 제안이 명시적으로 버렸다(「진행중은 착지하면 지워지는 항목이라 성립하지 않는다」). 만들지 않았다. |

★**⒞ 를 «스크립트 없이» 고른 이유**: `REPORT.md` 가 이미 이 저장소에서 같은 처방으로 돌고 있다
(고정 안내 + 정본은 딴 데). ★**선례를 따랐지 발명하지 않았다.**

## F3 — 충돌이 실제로 줄었는가

**⒜ 열린 PR 두 개를 «순서 바꿔» 실제 `git merge`**(격리 워크트리 · 두 브랜치 무접촉):

```
처방 «전»  #98 → #99 : CONFLICT — REPORT.md STATE.md
           #99 → #98 : CONFLICT — REPORT.md STATE.md
처방 «후»  #98 → #99 : clean
           #99 → #98 : clean
```
※「후」는 세 판본(merge-base·#98·#99) 모두에 처방을 이식한 합성 커밋이다 — ★**남의 브랜치엔 커밋 0**.
※「전」의 `REPORT.md` 충돌은 이 두 PR 이 **2026-09-07 이관보다 오래돼서**다(새 회차엔 없는 축) —
그래서 「후」에서는 그 축도 이관 후 판으로 맞춰 **`STATE.md` 만 남겼다**.

**⒝ 과거 10쌍 전수** — ★**이쪽이 정직한 수다**:

| | 충돌 |
|---|---:|
| 처방 전 | **10 / 10** |
| 처방 후 | ★**3 / 10** |

★★**0 이 아니다. 「0 이 아니다」라고 적는다.** 잔여 3건의 첫 충돌 줄은 ★**전건 `## 완료 (최근)`** 안이다
(63행 · 3/3). ⇒ ★**남은 지점은 «완료의 맨 위» 하나**이고 이 회차의 범위가 아니다(`#114` 가
「완료 분할은 하지 않는다」로 이미 판단했고 그것을 뒤집지 않았다). 후속 제안으로 올렸다.
★**차이의 이유도 분명하다**: #98·#99 는 «작성» 회차라 완료를 안 만지고, 잔여 3쌍은 «착지끼리»라 만진다.
