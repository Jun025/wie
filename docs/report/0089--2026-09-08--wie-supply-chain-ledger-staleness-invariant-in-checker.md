## F1 — 먼저 쟀다

**⑴ 「경고」의 출처 도구 = `cargo audit`**(무-플래그). 근거는 `rust-audit.yaml:80` 의 `run: cargo audit` 이고,
`deny.toml`·`audit.toml`·`.cargo/audit.toml` **전건 부재**(재확인) ⇒ `cargo deny` 축은 이 저장소에 없다.
★**검사기는 `cargo audit --json` 을 쓴다** — 사람이 보는 텍스트와 **같은 도구·같은 실행**이다.

**⑵ 지금 두 집합은 «같다»**(직전 회차가 방금 맞췄으니 그럴 것이라던 예상대로):

```
LEDGER-A  docs/project-kb/02_status.md §A ↔ cargo audit 실제
  §A 행 2건 · 경고 2건 · 절 머리 선언 2건
    · 일치: A-1 ttf-parser@0.25.1 RUSTSEC-2026-0192
    · 일치: A-4 chacha20@0.10.0 yanked
OK 대장 A 가 실제와 일치한다        rc=0
```
⇒ **양방향 차 0.** 해소할 차가 없었다.

**⑶ ★「A 행」의 정의** — 이것이 불변식의 절반이다:

> 줄머리가 **`| **A-<n>** |`** 인 표 행 **만**. C 로 옮긴 해소분은 `| **C-2**<br>(구 **A-2**)` 로
> 시작하므로 **세지 않는다** — 구 ID 병기는 셀 «안»에 있지 줄머리가 아니다.

★**왜 C 를 빼는가**: C 절 자신이 「A 의 불변식 **밖**이다(해소분은 `cargo audit` 이 더는 출력하지 않는다)」고
못박는다. ⇒ ★**정의를 그 문장에 맞췄지 새로 발명하지 않았다.** 실측으로도 확인했다 — C-2·C-3 이 셀 안에
`구 **A-2**`·`구 **A-3**` 을 담고 있는데 파서는 **2건**을 센다(4건이 아니다).

## F2 — ⒝ 집합 동등을 골랐다 · 버린 이유

| 안 | 판정 | 이유 |
|---|---|---|
| ⒜ 수 동등 | ★**기각** | ★**선행 사고를 못 잡는다.** 2026-09-06 사고는 **계수 2 ↔ 2 로 같고 구성만 달랐다** — 아래 **M3** 가 그것을 재현한다(행 2 · 경고 2 인데 red). ★계수 비교였다면 **조용했다** |
| ★**⒝ 집합 동등**(양방향) | ★**채택** | 그 사고를 정확히 잡는다. 대가는 **식별자 정규화** — 아래에 규칙을 적었다 |
| ⒞ ⒝ + C 행 정합 | ★**기각(그러나 절반은 공짜로 얻는다)** | ★**「C 로 너무 일찍 옮겼다」는 ⒝ 가 이미 잡는다** — 그 경고가 아직 나오는데 A 에 행이 없으면 «경고에만 있다»로 운다. 남는 것은 「한 번도 경고난 적 없는 C 행」뿐인데 그건 문서 품질 문제이고, C 표는 **열 순서가 A 와 달라**(자문·대상이 뒤바뀜) 파싱 표면만 늘린다. ★도달성 판정 기계화는 **범위 밖**이라 애초에 하지 않는다 |

★**식별자 정규화(⒝의 대가)** — 양쪽이 같은 키를 내도록:

```
audit  키 = package@version  +  (advisory ?? kind)
ledger 키 = package@version  +  (RUSTSEC id · 없으면 "yanked")
```
★**`kind` 를 키로 쓰지 않은 이유**: 대장은 성격을 산문으로 적는다(`` `unmaintained`(informational) `` ·
「취약점 아님 — 레지스트리 신호」) ⇒ 키에 넣으면 **한국어를 파싱**하게 된다. ★**advisory id 가 더 강한
식별자**이고, yanked 행은 그것이 없으며 `cargo audit` 도 yanked 에 `advisory=null` 을 주므로 **양쪽이 같은
자리에서 `yanked` 로 떨어진다.** 버전은 대장 5열의 `→` **앞** 첫 백틱 토큰에서 읽는다.

★**덤으로 «절 머리 선언 수»도 본다** — `### A. 권고·공급망 N건` 의 N 도 낡는 수다(M2 가 그것을 잡는다).
