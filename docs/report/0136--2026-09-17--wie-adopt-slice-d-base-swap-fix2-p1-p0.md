## ⓑ 같은 축이 있는가 — **절반은 이미 있었다. 그 절반은 «다시 만들지 않았다»**

| 제안이 말한 값싼 절반 | 실측 | 처분 |
|---|---|---|
| ⒜ claim 조회에 **draft** 포함 | ★**이미 포함**이다 — `gh pr list --state open` 은 draft 를 «열린 PR» 로 준다 | **불요** |
| ⒜ claim 조회에 **방금 push 된 브랜치** 포함 | ★**살 수 있는 시간이 ≤70초다**(아래 ⓒ) | ★**기각** |
| ⒝ 충돌 시 **무엇을 옮길지 도구가 출력** | 착지 «후» 경로엔 **이미 있다**(`::error` 문안이 「아직 착지하지 않은 쪽을 옮겨라」) | ★**열린 PR 끼리일 때는 그 규칙이 «모호»했다**(양쪽 다 미착지) ⇒ **그 자리에만** 결정 규칙을 넣었다 |

## ⓒ ★**제안의 처방을 그대로 쓰지 않은 근거 — 창의 «위치»를 쟀다**

제안은 처방으로 「claim 조회를 브랜치까지 넓혀라」를 들었다. **그 창을 직접 쟀다** — `docs/report` 를 더한
**PR 32건**의 「파일 커밋 → PR 생성」 간격:

```
n=32   min=3s   p50=28s   max=70s
```

⇒ ★**«PR 이 아직 아니어서 안 보이는» 구간은 최대 70초**다. 그런데 실제 충돌은 **5분·8분** 간격에서 났다
⇒ ★**넓혀도 못 막는다.** ★**진짜 창은 «조회 → 커밋»**, 즉 **회차의 작업 시간**이고 그것은 분 단위다.
⇒ 그래서 고친 자리는 «조회»가 아니라 ★**«커밋 시점에 이미 잡혀 있는가»를 재는 축**이다 —
그 축은 회차가 커밋 전에 돌리는 **기본 모드**이자 CI 가 PR 마다 돌리는 **같은 명령**이다.

## ⓓ 산출물

- `crossPrCollisions(mine, prClaims)` — 순수 함수. ★**«같은 파일명»을 내 PR 자신으로 보고 거른다**
  ⇒ 자기 PR 번호를 알 필요가 없다(두 회차가 같은 번호를 잡으면 슬러그가 달라 파일명이 반드시 갈린다).
- `myAddedNames(disk)` = 디스크 − `origin/main`. ★**전체 디스크로 대조하지 않는 이유**: 그러면
  ★**나와 무관한 두 PR 의 충돌이 내 PR 을 red 로 만든다**(오탐). ★**커밋 전 untracked 파일도 잡힌다** — 그것이 이 축의 자리다.
- 실패 처리는 이 파일의 기존 원칙 그대로 — **git·네트워크 실패 = 경고**(막지 않는다).
- ★**main push 빌드는 «네트워크를 아예 안 친다»**(더한 것이 0이면 조회 자체를 건너뛴다).
- `engine-contract.yml`: `pull-requests: read` + 그 스텝에 `GH_TOKEN` ★**두 줄** — 없으면 CI 에서
  `gh` 가 404 로 죽어 이 축이 **조용히 경고로 강등**된다(= 「있는데 못 도는 검사」).

## ⓔ ★개악 대조(양방향 · **제품 호출부** · 실데이터)

내 회차 파일을 **일부러** `0134`(= #177 이 들고 있는 번호)로 두고 기본 모드를 돌렸다:

★**상수 대 상수가 아니다** — 대조의 «상대»는 **지금 열려 있는 실제 PR #177** 이고, 판정은 제품 호출부가 냈다.
`--selftest` 는 **15케이스 전건 일치**(신규 6: 잡는다 / 다른 번호 오탐 0 / 자기 PR 제외 / 더한 것 0이면 남의 충돌 무시 /
git 축 실재 / ★호출부 슬라이스 — 함수만 두고 호출을 지우면 이 축이 운다).

## ⓕ 잃는 것 — **적는다**

- ★**PR 빌드가 네트워크를 친다**(열린 PR 수만큼 `gh api` — 오늘 4건). 실패하면 **경고**라 red 는 아니지만,
  ★**그만큼 «조용히 못 보는» 회차가 생긴다.** 이 항이 「검사가 있다」를 「검사가 돌았다」로 읽지 못하게 하는 자리다.
- ★**충돌이 나면 «각자 다음 run 부터» 두 PR 이 red** 다 — ★«즉시»가 아니다(체크런은 커밋에 묶인다).
  그래서 규칙을 **기계가 찍되 축을 «시간»으로 잡았다**: ★**나중에 claim 한 쪽이 옮긴다**.
  ★**그 축이어야 «통보받은 쪽 = 움직일 쪽»이 된다** — 늦게 claim 한 쪽이 먼저 빨개지는데 규칙이 «PR 번호»였다면
  red 를 본 쪽은 가만히 있어야 하고 움직여야 할 쪽은 아직 모른다(게이트² F3). ★규칙 없이 red 만 내면 두 회차가 서로 기다린다.
- ★**«안 하면»**: 지금처럼 **착지 후에** 빨개진다 — 그 시점엔 머지 회차가 남의 PR 파일을 고쳐야 하고,
  실제로 **오늘만 두 쌍**(#164·#165 / #176·#177)이 그 상태로 열려 있었다.

**사용자 영향**: 회차가 커밋 전에 돌리는 그 명령이 **「남이 이미 그 번호를 들고 있다」**를 그 자리에서 말한다.
지금까지 이 사실은 **착지한 뒤에만** 드러났고, 드러났을 때는 고칠 사람이 원 작성자가 아니었다.
