## [2026-09-07] 재측 판정이 «마지막에 붙은 행»이 아니라 «가장 높은 행»을 읽는다 — ⒜ 채택 (wie-worklog-coverage-last-vs-max-decision)

**무엇을**: `scripts/check-worklog-coverage.mjs` 의 `record.measurements.at(-1)` 을 ★**`landedRounds` 최대 행**(동률은 나중에 붙은 쪽)으로
바꿨다. ★**비-주석 변경은 «한 줄»**이고, ★**임계(`WINDOW=10`)·`THRESHOLD=70`·「비율은 사람이 판단한다」 설계는 무접촉**이다.

**왜 — ★F1⑶ 이 「단조」인데도 ⒟ 를 고르지 않았다**: `origin/main` 의 `measurements` 는 `[13,23,33,43,53]` 로
★**엄격 단조 · 중복 0 · `at(-1) == max`** 다. 즉 순서 역전은 **아직 일어난 적이 없다**.
★★**그러나 «그 전제 조건»은 이미 일어났다**: `80809604`(#120 브랜치)와 `ed70b279`(#122 브랜치)가
★**각자 `landedRounds: 53` 을 append** 했고, 둘이 **바이트 동일**이라 한 행으로 접혔을 뿐이다.
두 브랜치의 `landed` 가 하나라도 달랐으면 두 행이 남고 순서는 **머지 순서가 정한다**.

**왜 «게이트 약화»가 아닌가 — 세 경우를 실행해서 갈랐다**(같은 집합, 순서만 다름):

| 원장 | 옛 판본 `at(-1)` | 새 판본 `max` | |
|---|---|---|---|
| `[…, 50, 40]` 순서 역전 | **rc=1** | **rc=0** | ★**거짓 red 제거** |
| `[…, 40, 50]` 정순 | rc=0 | rc=0 | 불변 |
| `[…, 40, 45]` 진짜 기한 초과 | rc=1 | ★**rc=1** | ★**여전히 red** |

⇒ ★**움직인 것은 «순서 역전» 한 경우뿐이고, 그 red 는 «약속이 지켜졌는데» 뜨던 것**이다(50에서 잰 기록이 원장에 있다).
★**BELOW 축은 «단방향 강화»가 아니라 «최신 행»을 양방향으로 따른다**(게이트② 보정 ⒠ · 재현했다): `[…, {56, pct 50}, {50, pct 100}]` 은 옛 **rc=0** → 새 **rc=1** 이고, ★**거울** `[…, {56, pct 100}, {50, pct 50}]` 은 옛 **rc=1** → 새 **rc=0** 이다 — 둘 다 «낡은 행을 무시한다»는 같은 규칙이고 OVERDUE 축과 같은 행을 읽어 일관된다.

**사용자 영향**: 없다(원장 검사기). 실제 원장에서 **rc=0 무회귀**. ★**남는 한계**: 이 script 계열은 시험 하네스가 없어
세 경우가 «영구 잠금»이 아니다 — 그래서 그 세 줄을 ★**헤더 주석에 «재실행 가능한 형태»로** 남겼다.
