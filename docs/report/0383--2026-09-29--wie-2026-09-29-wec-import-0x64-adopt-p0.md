## [2026-09-29] LGT `Runnable.run` 은 고정 slot 10 이 아니다 — 인터페이스 참조 칸이 가리키는 slot · 월드장기체스 AI 차례 정지 해소 (wie-2026-09-29-wec-import-0x64-adopt-p0)

**무엇을**: LGT AOT 클래스의 vtable slot 에 인터페이스 ABI 행의 이름을 붙일 때, 고정 index 대신 **그 클래스의 인터페이스 참조 칸(reference cell) 둘째 워드**를 기준 slot 으로 쓴다.
`java/lang/Runnable` 행의 `index` 는 이제 slot 이 아니라 **인터페이스 안 메서드 순번**(`run` = 0)이다. 칸이 없는 경로(이름 목록으로 온 인터페이스)는 종전 가정(Object 의 `vtable_size` 10)을 그대로 쓴다.

**왜**: 0377 이 남긴 한계 — 월드장기체스 연습 대국에서 판이 뜬 뒤 키가 화면을 바꾸지 못하고 「사용시간」이 멈춘다(4/4 `frozen_tail_steps` 12).

**사용자 영향**: 연습 대국(체스·장기)에서 컴퓨터 차례가 오면 판이 영원히 멈추던 것이, 컴퓨터가 수를 두고 사용자 차례로 돌아온다. 그다음 대국 중 메뉴의 「계속하기」에서 새 벽(`java/lang/Integer vtable index 12`)을 만난다 — 후속 제안.

### 먼저 배제 — 키 순서 문제가 아니다

`--keys` 로 판 위 경로를 적어 재현했다(스크립트는 `game_lab` 밖 스크래치):

```
WAIT:6 OK:3 OK:3 OK:3 WAIT:4 OK:3 WAIT:3            # 안내 → 로고 → 타이틀 → 메인 메뉴
DOWN:2 OK:3 WAIT:2 OK:4 WAIT:3 OK:4 WAIT:4 NUM1:4 WAIT:4   # 연습하기 → 장기연습 → 상차림 1 → 판
HASH:3 NUM1:3 OK:3 WAIT:5 ×6                       # #키 확장 화면 → 1.한수쉬기 → 「네」 → AI 차례 대기
```

- 판 위 커서 이동은 **된다**(main 에서 `UP/LEFT/RIGHT` 마다 프레임이 바뀌고 사용자 시계가 0:00:03 → 0:00:50 으로 간다 — 멈춘 게 아니다).
- 확장 화면의 모달 「한 수 쉬시겠습니까?」도 정상이다: `OK`·`NUM1` = 예(진행 1수) · `NUM2` = 아니요 · `RIGHT`+`OK` = 아니요.
- **멈추는 곳은 AI 차례 하나다**: 한 수를 넘기면 진행 1수에서 AI 시계가 0:00:00 인 채 40초 동안 프레임이 같다(main · #406 이전 `313ddcd8` 모두 2/2). 기본 27키 스크립트가 도달하는 체스판에서도 같다 — 사용자가 수를 둔 뒤 사용자 시계 0:00:01 에서 정지(원 제보의 그 화면).
  #406(paint 직렬화)은 원인이 아니다 — `313ddcd8` 과 main 이 같은 경로에서 같은 결과.

### 원인 — `Thread.start` 가 AI 객체의 `run()` 대신 paint 계열 메서드를 돌린다

계측(임시 `warn!` · 커밋 안 함, release 1판씩):
- `RUST_LOG=debug`: 한 수를 넘기는 순간 `Thread::<init>(t, r, name)` → `start` → 새 스레드 3 이 `Thread::run` 직후 `Object::wait(r)`. 이어 **이벤트 스레드 2 도** paint 안에서 `Object::wait(r)`. 그 뒤 `notify` 는 0 — 두 Java 스레드가 같은 객체에서 영원히 잔다(이후 로그 0줄).
- 두 `wait` 의 lr 이 **같은 호출부 `0x305c8`** 이다. binary.mod(`objdump --triple=armv5te`) 로 읽은 그 함수 `0x304b0` 은 `(this, g)` 메서드다:
  `if (f.bc != f.c0) { try { synchronized (this) { this.wait(); } } catch … }` 다음 r1(`g`) 로 그리기를 한다. 이벤트 스레드는 r1 = kwis `Graphics`(`0x4884a010`) 로, AI 스레드는 r1 = 0 으로 들어온다.
- 즉 AI 스레드의 `run` 이 **paint 경로**다. 클래스 링크 시점의 slot 이름 붙이기를 찍으니(`prepare_generated`):
  `l extends m implements java/lang/Runnable` · vtable 67 · 부모 `m`(게스트 클래스) 15칸 · slot 10 = `0x37504` 가 ABI 행 `Runnable.run = 10` 으로 **`run()V` 로 등록**됐다.
  그런데 `0x37504` 는 인자 하나를 받아(`mov r5, r1`) **부모 `m` 의 slot 10 `0x3a6d4` 를 비가상 호출**(`this, r1` 그대로)하는 오버라이드다 — `super.xxx(x)`. `run()V` 가 아니다.
- `l` 의 진짜 `run` 위치는 클래스 기술자의 인터페이스 참조 칸에 있다: `ptr_interface_references` → `[1][→칸]`, 칸 = `[→"java/lang/Runnable"][0x3f]` — **63**. slot 63 = `0x39d28` 은 `this` 만 쓴다.

### 칸의 둘째 워드 = 그 클래스가 인터페이스 첫 메서드를 둔 slot — 코퍼스 검증

`game_lab/*/lgt` 의 `binary.mod` 를 걸어 외부 인터페이스 이름을 가리키는 칸을 모두 읽었다(`java/lang/Runnable` 29칸 · 15타이틀):

| 둘째 워드 | 칸 수 | 그 클래스 모양 | slot 10 |
|---|---|---|---|
| 10 | 8 | `extends Object` 6 · `extends TimerTask` 2 (vtable 11~28) | 곧 칸이 가리키는 slot |
| 11 | 17 | `extends Thread` — `Thread.run` = 11, 이 파일의 Thread 행과 일치 | 0(상속한 `start`) |
| 11 | 1 | `73f3a21e981c` `c_bk` · 부모가 게스트 클래스(사슬은 따라가지 않았다) · vtable 41 | 0 |
| 11 | 1 | 메이플스토리2007 `r extends Object` · vtable 12 | `0x6149d`(Thumb) — `run` 이 아닌 다른 메서드 |
| 16 | 1 | 월드장기체스 `i extends Object` · vtable 19 | `0x25910` — r1 을 읽는다(인자 있음) |
| 63 | 1 | 월드장기체스 `l extends m` · vtable 67 | `0x37504` — 위의 1-인자 오버라이드 |

- 10 행과 `Thread` 하위 11 행은 이미 옳게 돌던 경우(slot 10 이 곧 `run`, 또는 부모 `Thread` 항목이 slot 11 을 `run` 으로 이름 붙임)라 이 변경으로 **이름이 바뀌지 않는다**.
  바뀌는 것은 3칸이다: 월드장기체스 `i`(16)·`l`(63), 메이플스토리2007 `r`(11 — 종전엔 slot 10 이 `run` 으로 붙었다).
  `c_bk` 는 slot 10 이 비어 종전에 `run` 이 붙지 않았다 — 부모가 slot 11 을 이름 붙이면 불변, 아니면 이번에 이름이 새로 생긴다(잘못 붙던 것이 바뀌는 경우는 아니다).
  메이플스토리2007 전/후(기본 `--inject` 각 3판 동시): 둘 다 3/3 `UNMEASURED · max-ticks` · 키 22~23/27 · paints 216~229 · content true — 기본 스크립트 범위에서 차이 없음(그 클래스의 스레드가 이 27키 안에 시작되는지는 재지 않았다).
- 게스트가 정의한 인터페이스를 가리키는 칸(클래스 포인터)은 둘째 워드가 0 이거나 무관한 값이라 **읽지 않는다**(외부 이름 경로에서만 읽는다).
- 인터페이스 메서드가 둘 이상일 때 `기준 slot + 순번` 이라는 것은 **검증하지 못했다** — ABI 에 인터페이스 행은 `Runnable`(메서드 1개)뿐이다.
