## [2026-09-17] resize 의 «뒤 버퍼»를 앞 캔버스로 읽어냈다 — 디버그 게터도, 새 게스트도 없이 (wie-adopt-resize-fixture-scenario-g-p0)

### 무엇을

Scenario **G2** 를 더했다. 새 픽스처 `test_data/resize_draw_ktf.zip` = 커밋된 `keydraw_ktf.zip` + ADF 한 줄
(`DisplaySize:320*400`), 같은 바이트 안정 생성기의 두 번째 산출물이다. **Scenario G 는 한 글자도 고치지 않았다.**

### 왜

채택 제안 `2026-09-17-resize-fixture-scenario-g#p0` 의 전제를 재고 **지금도 참**임을 확인했다 —
`WebScreen` 의 `back_canvas` 는 `wie_featurephone/src/lib.rs:94` 에서 `document.create_element("canvas")` 로 만들어
**DOM 에 붙지 않는다**(`appendChild` 0). ⇒ 어떤 셀렉터로도 JS 가 못 읽고, 뒤 버퍼만 옛 크기로 남으면
`drawImage` 는 **throw 없이 자른다** ⇒ G 의 두 단언을 모두 통과한다.

### 제안의 tradeoff 두 길을 «둘 다» 쓰지 않았다

제안은 ⑴「리사이즈 후 그리는 게스트를 새로 빌드 — nightly+네트워크 생성기가 하나 는다」 또는
⑵「wasm 에 디버그 게터 — 계약 표면을 검증 목적으로 넓힌다」라고 적었다. **둘 다 불필요했다.** 열쇠는 둘:

1. ★**키우는 방향으로 리사이즈한다.** 기존 G 는 **줄인다**(240x320 → 176x220) — 그런데 줄일 때는
   낡은 뒤 버퍼가 **원리적으로 안 보인다**(큰 back 을 작은 front 에 `drawImage` 하면 잘리지만, 복사되는
   좌상단이 **정확히 프레임**이다). **키우면**(240x320 → 320x400) 옛 크기 «바깥»이 **아무것도 복사되지 않는다.**
2. ★**판별자는 «색»이 아니라 «알파»다.** `WebScreen::paint` 는 게스트 프레임 전체에 **알파를 강제로 불투명**하게
   칠하고(`Force opaque alpha: the core treats the framebuffer as XRGB`), `set_width` 직후의 캔버스는 **투명**이다.
   ⇒ 게스트가 그 구석에 **아무것도 그리지 않아도** 성립한다 — 배경이 곧 증거다.

그래서 «리사이즈 후 그리는 게스트»를 새로 만들 필요가 없었다. **`keydraw_ktf.zip` 이 이미 커밋돼 있고**
필요한 성질은 「그리기만 하면 된다」뿐이다. 다만 ★**helloworld 로는 안 된다** — 한 번도 paint 하지 않으므로
blit 자체가 없고 양쪽 다 알파 0 이 된다. 그것이 이 픽스처가 keydraw 파생인 이유다.

### 개악 대조 — 양방향, 제품 호출부

`wie_featurephone/src/screen.rs` 의 `WebScreen::resize` 에서 `back_canvas.set_width/set_height` **두 줄을 제거** →
`npm run build:wasm` → 라운드트립:

| | 결과 | G2 알파 검사 |
|---|---|---|
| 정상 | **53/53 · rc=0** | `rgba(0,0,0,255)` at (241,321) |
| ★개악 | **52/53 · rc=1** | ★`rgba(0,0,0,0)` — 투명 |
| 복원 | **53/53 · rc=0** | `rgba(0,0,0,255)` |

★★**그 개악에서 Scenario G 는 3검사 «전부 green» 이었다.** 제안이 이름 붙인 사각이 **그대로 재현**됐고,
그것이 G2 가 새 자리를 덮는다는 직접 증거다.

### 사용자 영향

리사이즈 후 화면이 **잘리는** 회귀가 이제 CI 에서 빨개진다. 종전에는 잘려도 예외가 나지 않아 아무도 몰랐다.

### 한계 — 숨기지 않는다

- ★G2 가 단언하는 것은 「옛 경계 바깥이 칠해졌다」이지 **뒤 버퍼의 `width` 값 자체가 아니다** — 여전히 JS 는
  그 캔버스를 못 읽는다. 즉 **직접 관측이 아니라 «관측 가능한 귀결»**이고, 같은 귀결을 내는 다른 구현으로
  바꾸면 통과한다.
- ★**줄이는 방향은 여전히 못 본다**(위 1 의 이유). 그래서 기존 `resize_ktf.zip` 을 **남겨 두고** 별 픽스처를 더했다.
- ★알파 판별자는 `paint` 의 «알파 강제 불투명» 정책에 기댄다. 그 정책이 바뀌면 이 검사는 red 가 아니라
  ★**«항상 green»** 으로 조용히 무의미해진다.
- ★**KTF 경로만** 덮는다(G 와 같다) — LGT·SKT 의 resize 는 여전히 픽스처 0. 후속 제안으로 남겼다.
