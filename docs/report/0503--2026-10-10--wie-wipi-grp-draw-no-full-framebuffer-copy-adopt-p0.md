## [2026-10-10] WIPI-C 그리기가 호출마다 화면 전체를 복사하지 않게 — 그린 영역만 게스트 메모리와 주고받는다 (wie-wipi-grp-draw-no-full-framebuffer-copy-adopt-p0)

채택: `2026-10-10-lgt-speed-shortfall-root-cause#p0`(0501).

### 무엇을

- `primitives::write_canvas` 가 도형마다 **경계 상자 ∩ 클립 ∩ 프레임버퍼** 를 구하고, 그 영역만 게스트 메모리에서 읽어 그리고 되쓴다.
  비면 아무것도 하지 않는다(종전에도 그 경우 그려지는 픽셀은 0 이었다).
  - 상자: 점 1×1 · 채우기/사각형/호/그림/영역 복사/프레임버퍼 복사 = `(x, y, w, h)` · 선 = 두 끝점의 상자(+1) · 글자·`MC_grpSetRGBPixels` = 상자 없음(클립 전체 — 글리프 범위는 폰트 몫이고, 후자는 좌표가 `wrapping_add` 로 감긴다).
  - 계산은 i64 — 게스트 극단 좌표가 넘치지 않는다.
- `FrameBuffer::canvas(context, region)`: 캔버스 이미지는 `WindowImageBuffer` — **너비·높이는 프레임버퍼 그대로**이고 픽셀은 영역 것만 들고 있다.
  그래서 캔버스가 하는 모든 클리핑 판단(`clip_segment` 의 Liang-Barsky · `stroke_arc` 의 단계 상한 · `draw_rect` 의 오른쪽/아래 변 검사)이 종전과 **같은 입력**을 본다.
  영역 밖은 0 으로 읽히고 쓰기를 버린다. 영역은 연산에 클립으로도 넘겨, 상자를 잘못 잡아도 영역 밖이 바뀔 수는 없다(빠질 수만 있다 — 그건 아래 시험이 잡는다).
- 행 보폭은 종전 `data()` 와 같은 `width × bpp`(게스트 `bpl` 을 안 본다 — 동작 보존). 전체 너비 영역은 한 번에, 아니면 행마다 옮긴다.
- 픽셀 연산 블릿(`blit_with_pixel_op`)·`MC_grpFlushLcd`·그림/복사의 **원본** 읽기는 손대지 않았다(원본 전체 읽기 — 프레임당 1~수 회라 0501 프로파일에서 작다).

### 시험 — 클립·투명색·오프스크린을 «종전 경로와 같은 결과»로 잠근다

`region_tests::drawing_through_a_region_matches_drawing_the_whole_buffer`: 패턴으로 채운 버퍼에 9종 연산(점·채우기·선·사각형·호·채운 호·그림·영역 복사·프레임버퍼 복사)을 결정적 난수로 400회씩,
16/32bpp × 버퍼 4개(64×48 · 9×11 · 31×7 · 1×1 — 원본보다 좁고 넓은 오프스크린) 에서 돌려 **종전 방식(전체 읽기 → 전체 캔버스 → 전체 되쓰기)과 바이트 단위로 비교**한다.
클립은 1/3 전체 · 2/3 무작위(음수·초과·`i32::MIN/MAX` 근처 포함), 좌표·크기도 극단을 섞는다. 원본 그림은 픽셀 절반이 알파 0 — 키 색(마젠타)은 `image_alpha`/LBMP 디코드를 거쳐 알파 0 으로 도착하므로 «투명색» 축이 이것이다.
영역이 작으면(픽셀 유실) 또는 영역 밖을 건드리면(패턴 변경) 모두 드러난다.

- 되돌리면 red(각각 확인 · 원상 green): 선 상자의 x `+1` 제거 → `kind 2`(선) FAILED · 행 나눔 무력화(늘 한 번에 옮김) → `kind 5` FAILED.
- 영역 대신 원래 클립을 연산에 넘겨도 green 이다(예상대로 — 캔버스 연산은 클립을 지키고 창 밖 쓰기는 버려진다). 영역을 클립으로 넘기는 것은 이중 안전이지 결과를 바꾸지 않는다.
- 기존 클립 시험(0484 `drawing_stays_inside_the_context_clip` · `a_null_clip_resets_the_clip`)·픽셀 연산 시험(0447)·`wie-wipi-c` 68건 전부 통과.
