### 판정 — 전제가 틀렸다

주소는 `ed6ad7318ac9` 을 `wie-ktf-dump` 로 편 이미지 기준(sl = `0x271814`).

- 그 «표»는 게임 **스크립트 인터프리터의 내장함수(builtin) 표**다. `0x10aad4` 가 `*[sl+0x1a8]` 에 226칸(0..0xe1)을 채운다 — 기본값은 빈 함수 `0x108de5` 가 166칸, 나머지가 개별 함수이고 주소가 칸 순서대로 오름차순이다. `+0x384` = 내장함수 `0xe1`.
- 그 표를 읽는 곳은 `0x10b20c` 하나다: `id > 0x188` 이면 오류 `0xf`, 아니면 `table[id]` 호출. 이것을 부르는 곳도 하나 — 바이트코드 `0x92`(내장함수 호출) 처리기 `0x104a60`.
- 인터프리터 본체 `0x106ec8`: 16비트 연산 코드를 `*[sl+0x110]` 표로 돌리고 `0xf4` 초과(`0xff`)에서 끝난다.
  ⇒ `0xe1` 은 **스크립트가 부르면 실행되는 내장함수**다. 플랫폼이 부를 자리가 아니다. 구현할 콜백은 없다.
- 플랫폼 → 게임 입구도 실측했다(임시 PC 계측 · 커밋 0): 시작(`0x108d08`)과 키 이벤트(`0x108b94`, type 2/3)는 전부 닿는다.
  pause/resume/destroy 입구는 안 불리는데 실행 중이면 정상이다. 빠진 플랫폼 호출은 없었다.

### 실제 원인 — 첫 실행을 «저장 있음»으로 읽었다

- 게임은 부팅 때 스크립트를 한 번 돌린다(연산 약 3만 개 · 약 2초에 `0xff` 로 끝남). 그 안에서 `option.txt`·`coupon.txt` 를 연다.
- 엔진의 `fopen` 래퍼(`0x10c69c`) 가 존재 판정을 `0x10c600` 에 맡긴다: `return slot16(name, 1) == 0 ? 1 : -1`.
  읽기 모드는 이 값이 1 일 때만 연다(`MC_dbOpenDataBase(name, 8, 1)`), 새로 만들기 모드는 1 이면 실패한다.
  ⇒ **이 엔진에서 slot 16 의 0 은 «있음»이다.**
- #374 전 wie 는 없는 DB 에 0 을 돌려줬다 ⇒ 첫 실행에 두 파일을 «있음»으로 읽고, 빈 저장소에서 `stream_read` 7번이 전부 EOF(-23, 버퍼 미기록)였다.
  그 뒤 스크립트는 타이머를 켜는 내장함수(`0x95` → `0x10bae0`)를 한 번도 부르지 않고 끝난다 ⇒ 0334 가 본 «타이머 3칸이 끝까지 빔 · 상태 1 불변» 그대로다.
