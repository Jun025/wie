### 0x68 식별 근거 — 호출부(임시 계측 · 커밋 안 함)

`0x68` 스텁이 lr·r0..r3·lr 앞 코드를 찍게 하고 Thumb/ARM 으로 풀었다. 6종 공통:
1. 키 입력 처리에서 **표식 DB 를 쓴다**(`MC_dbOpenDataBase(…, 8=create)` → close, 또는 delete → 재생성).
2. `0x68` 을 **정수 1개**(r0)로 부른다 — 타이틀별 `0`·`2`·`0x1b`·`-1`. 포인터가 아니다.
3. **반환값을 쓰지 않는다**(예: `movs r0,#0x1b ; bl <bx r3> ; pop {r0} ; bx r0` — 바로 덮어쓴다).
4. 스텁이 0 을 돌려주면 안내 루프로 되돌아와 **키마다 다시 부른다**(`1352b27a7898`: 27키에 27회).

⇒ «프로그램을 끝내라». KTF 표는 이 자리가 `MC_knlMExecute` 지만 인자가 프로그램 이름이 아니므로 그 함수는 아니다 — 이름은 행동으로 지었다.
보강 1: 정적 스캔 — 코퍼스 LGT 77종 중 **75종**이 `0x68` 을 import 한다(첫 실행 안내가 없는 타이틀 포함 = 메뉴 «종료» 경로).
보강 2: 같은 빌드에서 `40b9537968de` 는 «게임을 종료하시겠습니까? 예» 에서 `0x68` 을 불러 끝났다(사용자가 고른 종료).

  빈 목록으로 답하는 것은 의미 발명이라 표를 fail-closed 로 둔다(후속).

### 엔진 몫 / 셸(otterpebble) 몫

- 엔진(이 PR): 게스트가 끝내라고 하면 `Platform::exit()` — featurephone 에서는 기존 sticky exit(«[wie] emulator requested exit») 경로.
- 셸 몫(고치지 않음 · 목록):
  1. sticky exit 를 받으면 **DB 를 저장(export)한 뒤** «다시 실행» 버튼을 보인다 — 첫 실행 안내 타이틀은 두 번째 실행부터 게임이다.
  2. 재실행은 **같은 DB 로** 부팅해야 한다(표식 레코드가 거기 있다). 새 세션·빈 DB 로 띄우면 안내가 무한 반복된다.
  3. 선택: 종료 직후 자동 1회 재실행 — 실기의 «EZ-i 메뉴로 이동 → 사용자가 다시 실행» 을 한 번 줄인 것. 사용자 선택 종료(메뉴 «종료»)와
     구별이 안 되므로(둘 다 같은 0x68) 자동은 권하지 않는다.
