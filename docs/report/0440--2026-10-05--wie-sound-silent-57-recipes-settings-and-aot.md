**무엇을**: 6차 전수(0432 §6) 의 `sound:silent` 57종을 행마다 다시 갈랐다. 엔진은 세 군데를 고쳤다.

- `wie-ktf` `OWNER_SOUND_OFF_SETTINGS`: 5행을 더했다.

`compat.json` 은 17행을 고쳤다. 소리 `no → ok` 11행, «소리가 나지 않을 수 있어요» → 게임 설정 안내 6행이다. 이용자 소식은 3건이다.

**왜**: 운영자 지시(2026-09-30·10-04): 소리 축 완성도. 0432 §6 의 «레시피 미적용 · 원 주인 설정 · AOT 조건 섞임»을 행 단위로 풀었다.

### 4. 엔진 결손 — 원인과 고침

#### 4-1. SMAF 뒤 여분 바이트(`wie-backend` `Audio::load_smaf`)

- 진단 빌드 덤프: 게임이 넘긴 13,000B 의 앞 10,201B 가 `MMMD` 파일이다. 선언 길이 `0x27d1` + 8, CRC `01e3` 이고, 뒤 2,799B 는 0이다.
- `smaf` 0.1.2 의 `Smaf::parse` 는 조각(chunk)을 슬라이스 끝까지 읽고, 그 뒤가 정확히 CRC 2바이트이길 요구한다. 그래서 여분 길이가 8로 나눈 나머지 6·7일 때 전체가 실패하고, `parse_smaf` 가 빈 목록을 돌려준다.
  - 시험 파일로 여분 1~16·2,799B 를 쟀다. 6·7·14·15·2,799 에서 사건 0이고, 잘라 파싱하면 전부 3이다.
- 고침: 전체 파싱이 빈 목록일 때만 선언 길이로 잘라 다시 파싱한다.
  - ★처음에는 «언제나 자른다»로 썼다. `wie-skvm` 시험(`play_is_not_restarted_while_the_clip_is_still_sounding`)의 SMAF 는 머리 길이가 0이라 그 판이 시험을 깨뜨렸다. 그래서 «종전에 파싱되던 것은 그대로»로 좁혔다.
  - 종전에 사건이 나오던 클립은 결과가 바뀌지 않는다. 이것은 구조로 보장된다.
- 되돌리면 red: `smaf_in_a_padded_buffer_still_plays_its_notes`. 재시도 분기를 끄면(`if false && …`) FAILED, 복원하면 통과(실측).
- 한계: MIDP `SmafPlayer` 의 길이 계산(`sequence_length_ms`)은 `parse_smaf` 를 직접 부른다. 여분이 붙은 클립은 재생은 되지만 `lengthMs` 가 0이다. 그 경로로 여분이 온 것은 이번에 관측하지 못했다.

#### 4-2. 시작 스레드가 붙은 채 남는다(`wie-jvm-support` `JvmSupport::finish_launch`)

- `66959afab216`(SKT) 의 javap:
  - `ResourceManager.l()` 은 `Thread.activeCount() == 1` 일 때만 음악 `Audio` 스레드를 만들어 `start` 한다.
  - `DragonEyes.c && activeCount() > 1` 이면 그냥 돌아간다.
  - 게임 루프는 `Display.callSerially` 다. 단말에서는 시스템 스레드 하나가 돌리므로 쉬는 동안 1이다.
