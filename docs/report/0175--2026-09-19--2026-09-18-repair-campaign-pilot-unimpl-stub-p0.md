#### ⒣-2 필수 2 — 「그 게임 자신의 파일 확장자다」를 **확정으로 적지 않는다**

같다 — ★어느 쪽인지는 확정하지 못했다**」. ★PR 제목도 같이 낮췄다(커밋 메시지는 이미 푸시돼 있어
`--force` 없이는 못 고친다 — 그 자리만 초판 문면이 남는다).

★가설은 **셋 → 넷**이다(⒟ 의 표). 추가분 **H4 = 「이후 호출이 해석될 디렉터리(네임스페이스)를 고르거나
보장한다」**. ★초판의 셋이 **전부 «확장자» 프레임 위에** 서 있었다는 것이 반려의 요지다.

★**H4 를 «세우려고» 재지 않았다 — H1 을 «확정으로 적을 수 없다»를 재는 데 썼다.** 패키지 실측:

#### ⒣-3 필수 3 — `SLOT8_TOKEN_MAX` 를 **시험이 고정**한다

초판 시험은 과길이 입력을 `[b'a'; SLOT8_TOKEN_MAX + 1]` 로 **상수 자신에게서** 만들어, 상수를 키우면
입력도 같이 커지는 **항진명제**였다. 시험 주석의 「a change that **widens** the filter fails here」가
그래서 **거짓**이었다. ⇒ **리터럴 `[b'a'; 17]` + `assert_eq!(SLOT8_TOKEN_MAX, 16)`** 둘 다 넣었다.

```
CONTROL  초판 시험 형태 + 16→64            → ★GREEN 38 passed; 0 failed   ← 검수자 M5 를 독립 재현
M5a      현 형태      + 16→64            → ★RED   37 passed; 1 failed
         panicked … assertion `left == right` failed: SLOT8_TOKEN_MAX is the only thing bounding
         what leaks into a log; widening it is a decision, not an edit
M5b      현 형태      + 16→64 + assert 삭제 → ★RED   37 passed; 1 failed
         panicked … slot 8 must not quote a token that is longer than SLOT8_TOKEN_MAX …
         got … measured r0=0x2200 ("aaaaaaaaaaaaaaaaa") …
RESTORED 원형(16 · 리터럴 17)              → GREEN 38 passed; 0 failed · `cargo fmt --check` rc=0
```
★**M5b 가 「둘 다 넣은」 이유다** — `assert_eq!` 가 언젠가 지워져도 리터럴이 혼자 문다.
★주석도 실제 동작에 맞춰 다시 썼다(거짓 주석을 남기지 않았다).
