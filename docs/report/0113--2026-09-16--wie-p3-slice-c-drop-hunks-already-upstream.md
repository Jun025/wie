## [2026-09-16] 조각 C — 이미 upstream 에 있는 엔진 hunk 삭제: 7행 착지 · 14행이 왜 아닌지를 수로 보였다 (wie-p3-slice-c-drop-hunks-already-upstream)

### 무엇을

조각 B(PR #158)가 「폐기」로 분류한 **21행**을 오늘 base 에서 지울 수 있는지 **행마다 실측**했다.

- ★**지웠다 — 7행**(`wie_wipi_java/src/classes/java/**` · `get_protos()` 46 → 42). 머지 예행 **74 → 67**.
- ★**못 지운다 — 5행**(#17~#21). 컴파일·린트·픽스처가 **실제로** 막는다.
- ★**보류 — 9행**(#1 · #9~#16). 컴파일은 되지만 **게이트가 그것을 보지 않는다**(운영자 판정).

측정 기록 정본 = `docs/upstream-realign-p3-slice-c-deletability.md`.

### 왜

**⑴ 「upstream 이 이미 가졌다」가 「오늘 지울 수 있다」를 함의하지 않는다.** 조각 B 의 분류는 옳았다 —
그것은 「머지가 우리 쪽을 버려도 되는가」를 답한 것이고, 이 회차의 질문은 그 다음이다.
#17~#21 에서 양쪽이 같은 코드를 가진 이유는 **중복이 아니라 «양쪽이 같은 RustJava 트레이트를 따랐다»**이다.
되돌려서 쟀다: #18·#19·#20 → `cargo check` **오류 10건**(`E0046 missing: identity, shallow_clone` ·
`E0407 destroy is not a member of trait ArrayClassInstance` ×3 · `E0277` ×4 · `E0061 attach_thread` 인자 수) ·
#17 → **beta clippy red**(`double_must_use`) · #21 → **`draw_j2me.jar` FAIL**(`image.rs:117` 에서 panic).
⇒ 그 다섯은 조각 D 의 머지가 upstream 쪽을 고르면 저절로 해소되지, 선행 삭제로 줄일 수 있는 것이 아니다.

**⑵ 제안 #p2 의 검증 논거를 시험했고, 9행에서 거짓이었다.** 논거는 「우리 base 위에서 지우면
4게이트 + 5픽스처가 **전부 살아** 검증이 강하다」였다. 실측: 되돌리기 전후로 `cargo test --all`
**179 passed / 0 failed 불변** · 5픽스처 **전건 PASS 불변**(`paints` 1/0/0/55/55 동일) · `cargo check` **오류 0**.
그런데 사라지는 것은 **Java 가시 메서드 18개 + 클래스 `org.kwis.msp.lcdui.ImageObserver` 등록**이다.
⇒ 그 green 은 «검증»이 아니라 «공허한 통과»다.

**⑶ 제안이 스스로 제시한 완화책이 이 9행에서 구조적으로 공허하다.** 「지우기 전 grep 으로 우리 안의
호출자 0건을 보여라」인데, 이것들은 `JavaMethodProto` 로 등록된 **게스트가 부르는** 메서드라
Rust 호출자는 **정의상 0**이다(17심볼 전수 계수: 14개가 0 · 3개가 1). 그 술어는 「안전」과
「유일한 호출자가 시험 불가능한 게임」을 **구별하지 못한다**.

**⑷ 그룹 A 의 삭제만은 근거가 «읽은 것»이 아니라 «잰 것»이다.** 삭제 **전** 원본 트리에서
`get_protos()` 를 전부 적재한 채 `new java/lang/VirtualMachineError()` 가 **`InstantiationError`** 를 던졌다.
우리 사본은 비-ABSTRACT 이고 `java_runtime@5b84dd1` 판본만 ABSTRACT 이므로, 그 예외가
**「런타임 정의가 이겼다」의 직접 증거**다(`java.class.path` = `RT_RUSTJAR : WIE_RUSTJAR : <jar>`).
사본은 2026-07-02(`5603a7f9`, 당시 포크 핀에 그 넷이 없었다) → 핀 이동 2026-09-04(`1762a32c`)
사이에 죽었고 아무도 알아채지 못했다.

**⑸ 대가를 수로 비교했다.** 머지 예행 실행값: 원본 **74** → 묶음1 후 **67** → (가정) 그룹 C 까지 **59**.
그룹 C 가 사는 것은 충돌 **8건**, 파는 것은 탐지되지 않는 메서드 **18개 + 클래스 1종**이고,
★그 8건은 전부 `UD`/`UU` 라 조각 D 가 upstream 쪽을 고르면 그냥 해소된다(upstream 판본이 그 18개를 다 갖는다).
게다가 **복원이 보장되지 않는다** — 조각 D 는 조각 A 에 걸려 있고 A 는 no-go 신호(`keydraw_lgt` upstream FAIL)를 들고 있다.

### 사용자 영향

**오늘은 없다.** 지운 7파일은 삭제 전에도 도달 불가였음을 실측으로 보였다(기능 델타 0). 5픽스처 전건 PASS ·
`cargo test --all` 178 → **179**(늘어난 1은 이 회차가 세운 잠금 시험이고, **기존 통과 수는 줄지 않았다**).
다음 회차에 나타난다: 조각 D 의 머지가 볼 미해결이 **74 → 67** 로 줄었다.

### 한계 — 숨기지 않는다

- **그룹 C 의 18개 메서드를 실제로 부르는 타이틀 수는 못 잰다** — Rust 호출자 계수가 이 축을 정의상 못 본다.
  있으면 잴 수 있는 것 = 292 코퍼스(계획 §4-2 · human-step 후보).
- **그룹 A 삭제가 원 커밋이 주장한 「5 KTF 타이틀」에 무해한가도 코퍼스 없이는 직접 못 잰다.**
  대체 증거는 위 `InstantiationError` 실측이고, 그것은 「사본이 애초에 안 쓰였다」를 말하므로 무해가 따라 나온다.
- **67 · 59 는 «예행» 수이지 조각 D 의 착지 수가 아니다.**
- **`docs/upstream-realign-p3-slice-b-triage.md` 는 이 브랜치에 없다** — PR #158 미머지. 이 PR 은 origin/main 에서
  갈라졌고 B 의 표를 **복사하지 않고 가리킨다**.
