### ⒝ 무엇을 쟀는가 — ★**슬롯 36 이 하는 일**(1게임 · 정적 + 실행)

표적 게임 1건(코퍼스 전체에서 `MC_knlReserved*` 를 치는 유일한 리포트). 호출부를 디스어셈블했다:
```
0x1034c0:  r1 = *[SL+0x10] 의 역참조 = WIPICKnlInterface 베이스
0x1034c6:  sub sp,#4                       ← ★스택 인자 자리
0x1034c8:  r0 = *[SL+0x14]
0x1034ca:  movs r3,#0
0x1034cc:  str  r3,[sp]                    ← ★★[SP+0] = 0  = «다섯째» 인자
0x1034d0:  r2 = -1
0x1034d2:  adds r1,#0x90                   ← ★필드 인덱스 36
0x1034d4:  r4 = *[knl + 0x90]              ← 피호출자
0x1034d6:  r1 = -1
0x1034d8:  bl __call_via_r4
```
⇒ ★**arity 는 5**: `f(r0, r1=-1, r2=-1, r3=0, [sp]=0)`.

★★**슬롯 동일성을 «두 축»으로 확인했다**(하나로는 부족하다): 폴트 덤프의 **`IP = 0x24` = 36** ·
구조체 오프셋 **`+0x90` = 필드 인덱스 36**. 그리고 `WIPICKnlInterface` 리터럴을 세어 `reserved4` 가
**인덱스 36** 임을 확인했다(전체 65필드).

**`r0` 은 문자열이다** — 형제 회차의 재배치 델타 방법(`+0x3428`, 덤프 `R0` 로 유도)으로 정적 해석:
★**`"MXUserMemInterf"`**. ★**교차검증**: 같은 델타가 `*[SL+0xc] = 0x1bfd08` 을 예측하고 **덤프의 `R5` 가
정확히 그 값**이다.

**반환값은 «인터페이스 포인터»다 — 호출부가 그렇게 쓴다**(`bl` 직후):
```
0x1034de:  str r0,[r5]        ; 전역에 보관
0x1034f0:  ldr r3,[r2]        ; ★ r3 = *ret = 반환된 표의 «슬롯 0»
0x1034f2:  bl  __call_via_r3  ; ret->slot0(buffer, 0x14400 = 82,944)
```
⇒ ★★**이름을 받아 인터페이스를 돌려주고, 호출부가 곧바로 그 슬롯 0 을 «메모리 풀 + 크기»로 초기화한다.**
`"MXUserMemInterf"` = *MX User Mem Interf(ace)* — **사용자 힙 인터페이스**로 읽힌다.

★**여기서 «이름»은 붙이지 않았다.** 모양은 「명명된 확장 인터페이스 조회」이고, 그것이
`Interface3`~`Interface16` 표들로 들어가는 문이라는 것은 ★**가설이다**(반환 포인터를 그 표 중 하나로
추적하지 않았다). 형제 회차(`…-p1`)가 같은 규율로 멈춘 그 자리다.
