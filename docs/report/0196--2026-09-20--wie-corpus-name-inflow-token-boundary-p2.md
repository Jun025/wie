### 무엇을 지었나 — 두 줄과 한 표식

1. **`scripts/lib/inflow-marker.mjs`**(신규) — 표식 정의·해시를 **한 곳**에 둔다. ★도구와 검사기가 같은 해시를 계산하므로, 두 벌이면 한 바이트만 어긋나도 **정상 회차가 red** 가 되고 그런 가드는 다음 사람이 지운다(`check-parity-lock-wired` 가 2026-09-06 에 치른 값).
2. **`scripts/corpus-name-inflow.mjs`** — 기본 모드에서 마지막에 한 줄을 찍는다:
   `<!-- corpus-name-inflow v1 subjects=N tree=<digest> B=… P=… S=… -->`
3. **`scripts/check-inflow-marker.mjs`**(신규) — `engine-contract.yml` 의 **항상 도는 `contract` 잡**에 실린 **진짜 게이트**(`continue-on-error` 아님). 대상 집합과 본문 digest 를 다시 계산해 표식과 대조한다. **코퍼스 불요.**

★**자기참조를 푼 방법**(이 설계의 유일한 비자명 지점): 표식은 **대상 파일 안에** 붙으므로 그냥 해시하면 **붙이는 순간 스스로를 무효화**한다. 그래서 **양쪽 모두 표식 줄을 «빼고» 해시한다**. 덕분에 「붙이고 → 검사」가 수렴하고, 옛 표식이 트리에 남아 있어도 같은 digest 가 나온다.

★★**그런데 «줄을 빼는 것»만으로는 부족했다 — 초판이 자기 green 케이스에서 red 가 났다.**
Markdown 에 표식을 붙이면 자연스럽게 **그 위에 빈 줄**이 생기고, 표식 줄만 제거하면 그 빈 줄이 남아 digest 가 움직인다
(실측: `92187e48c68ca4af` → `e8dae1d7538660db`). ⇒ 정규화에 **공백 축**을 더했다 — 빈 줄을 버리고 각 줄을 trim 한다.
★**안전한 이유를 «주장»이 아니라 «논증»으로 적는다**: 이 계수기의 판정은 **양옆 한 글자**가 단어문자인가뿐이고 공백은
**어느 쪽에서도 비단어**다. trim 은 줄의 앞뒤 공백만 건드리는데, 줄머리의 stem 앞은 이미 `\n`, 줄끝의 stem 뒤는 이미
공백이나 `\n` 이라 판정이 같다. 빈 줄 제거는 `\n\n` → `\n` 이고 둘 다 비단어다. **stem 은 개행을 가로질러 매치될 수
없으므로** 어떤 제거도 히트를 만들거나 없애지 못한다.
★**이 사고를 감추지 않는 이유**: 「표식을 붙였더니 red」는 다음 사람이 이 가드를 **지우는** 정확한 형태다.

### 가드 ① — 조용한 0 을 없앴다 (0189 의 실패형)

이제 그 경우 도구가 **표식을 찍지 않고** 이렇게 말한다:

```

   커밋한 «뒤» 다시 재라. 표식은 붙이지 않았다(0 을 굳히지 않는다).
```

★**«0 을 굳히지 않는다»가 요점**이다 — 이 도구의 자기 규격(「조용한 0 을 만들지 않는다」)을 그 자신에게 적용했다.
